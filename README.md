# cc-rights-license

管理作品权利、地域期限和授权协议。

## 主要业务规则

- **作品与权利人**：作品具有唯一编号 `workCode` 和多名权利人，每名权利人持有份额（`BigDecimal`，精度 9/小数 4 位）；全部份额之和必须精确等于 100%，否则作品创建失败。同一作品内权利人名称唯一（唯一约束）。
- **授权申请**：申请包含被授权方、一个或多个地域、一个或多个媒介、起止日期（闭区间，结束日期不得早于开始日期）以及类型（`EXCLUSIVE` 独占 / `NON_EXCLUSIVE` 非独占），创建后处于 `PENDING` 状态。
- **共同批准**：申请创建后收集权利人决定。只有同意份额累计达到 100% 才触发批准；任一权利人拒绝则申请立即终止（`REJECTED`）。每名权利人只能决定一次，决定记录只可新增不可修改；决定事件携带全局唯一的 `eventId`，重复提交同一事件号返回原结果（幂等），换事件号重复决定返回 409。
- **冲突检测**（按每个 地域 × 媒介 组合检查日期重叠，闭区间重叠即冲突）：
  - 批准**独占**申请时：不得与任何已批准授权（独占或非独占）重叠；
  - 批准**非独占**申请时：不得与已批准**独占**授权重叠，但可以与其他非独占授权并存。
- **原子批准**：多地域多媒介的整份申请要么全部生效（生成一条授权记录 `LicenseGrant`），要么整体失败；任一组合冲突则整份申请标记为 `CONFLICT` 并记录冲突原因，不会部分生效。
- **并发控制**：决定写入按申请行加悲观写锁；批准时对作品行加悲观写锁（`SELECT ... FOR UPDATE`）串行化同一作品的并发批准，冲突检查与授权落库在同一事务内完成，因此并发完成审批的冲突申请最多一个成功；失败申请保留全部决定记录并标记冲突原因。`(application_id, holder_name)` 与 `event_id` 唯一约束兜底防重。
- **查询接口**：作品授权日历（已批准授权按开始日期排序）、申请审批进度（已同意份额/剩余份额/决定明细/状态）、申请冲突明细（冲突授权及重叠的地域、媒介、期限）。

## REST 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/works` | 创建作品及权利人份额 |
| GET | `/api/works/{workCode}` | 查询作品 |
| POST | `/api/works/{workCode}/applications` | 创建授权申请 |
| GET | `/api/works/{workCode}/calendar` | 作品授权日历 |
| POST | `/api/applications/{id}/decisions` | 提交权利人决定（`eventId` 幂等） |
| GET | `/api/applications/{id}` | 查询申请 |
| GET | `/api/applications/{id}/progress` | 审批进度 |
| GET | `/api/applications/{id}/conflicts` | 冲突明细 |

## 开发环境

- JDK 21
- Spring Boot 4.1.1
- Maven Wrapper 3.9.9
- H2

## 本地运行

启动服务：

    ./mvnw spring-boot:run

运行测试：

    ./mvnw clean test
